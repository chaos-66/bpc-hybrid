# Stage 3 公式与评价修复结果（2026-09-07，development）

结论：本轮三个确定性缺陷已修复并在固定数据上真实离线重算；Sun 原三类公式结构、数据和阈值保留，不以分数上升作为验收条件。参考确定性抽取不是一个 LLM 方法臂。

根因与修复：

1. Sun Definition 6 的规则侧转换丢失 actor-action 关联，流程侧把整流程对象作为 C。现保留规则配对，按 pool.process_ref、lane.flow_node_refs、业务对象 activity_id 构建 f_m，并保留 Sun 的存在量词/最小相似度判断。缺失或不完整关联明确不可观察。
2. 新增时间比较把全流程时间文本当作同一动作的上限，并绕过映射门槛。现仅在动作映射通过、证据显式绑定该动作、规则为明确小时/天/周上限且不位于 applicability condition 内时使用数值矛盾。未关联计时器、下限、月年换算不产生“精确矛盾”。其余仍是已有相似度启发式，不能称完整逻辑验证。
3. 五分类统计丢失 abstention 和误判合规。现混淆矩阵为五个真实类别 ×（五个预测类别 + 无法判断列）；全部 80 对象入表，无法判断计入对应真实类别 FN，误判合规也计入合规类 FP，混淆矩阵和 paired evaluator 共用计数。

附带修复同一转换接口：有效 clause order_relations 按 action ID 转换，不再只计数后丢弃。既有 B0 胶囊仍无顺序关系，此修复不虚构输入，不改变其本次顺序结果。

验收边界：33 条人工违规标签（每类 11 条）与 40 对合成样本分开评价；新输出保存全部样本，旧输入/Gold/BPMN/原 Stage-2 预测哈希不变；不运行 API 或正式 Oracle。

## 原三类

参考抽取 Macro-F1 0.3889、Exact 0.3636；Rules-Only 0.3333、0.3333；修复前后两侧各 33 个最终判定全部不变。变化发生在执行者候选集合/不可观察原因等诊断上。Rules-Only 的 actor 检查 11 条均不可观察：动作映射不足 6、缺 actor-action map 1、缺 actor 2、关联不完整 2。所有 11 个 order 检查两侧均无通过阈值的顺序对，分数 0 不能解释成“顺序合规”；B0 源顺序关系为空仍是上游输入限制。

既有阈值网格已重算：γ=0.8 的 Macro-F1 0.3889，γ=0.6 的 0.8733，保持不变。0.6 仍仅为同一开发集 tested values 的描述性适配点；主阈值 0.8 不变，不是独立测试集上的提升。

## 可报告结论与剩余限制

禁止动作检出支持可行性；约束只有部分证据；条件与例外主要显示映射和 BPMN 可观察性不足。Stage 2 替换影响部分最终判断，但没有真实 Direct-LLM 下游结果，不能声称证明 LLM 端到端优于 Rules-Only。不得将 40 对合成的构造标签当人工 Gold 或七类正式 benchmark。
